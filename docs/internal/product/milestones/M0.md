# M0 — Workspace, contracts, and quality gates

**Kind:** crate delivery ·
**Depends on:** M-1 ·
**Serves:** NFR-51, NFR-52, NFR-53, NFR-55, NFR-56

## Goal

After M0 there is a Rust workspace that builds on both Linux targets, eleven
crates arranged so the dependency DAG is **wide and shallow**, and every trait
seam in `oqueue-core` has a fake beside it. No broker behaviour exists yet —
what exists is the shape everything else is written into, and the gates that
keep that shape from eroding.

⚠️ **This is the milestone where two constants stop being underived.** NFR-55
(coverage) and NFR-56 (pre-commit budget) cannot be chosen without something to
measure, and M-1 deliberately left them blocked rather than guessed. Choosing
them here is not a formality — a guessed threshold is indistinguishable from a
measured one a month later.

## Depends on

**M-1**, entirely. Every task here is executed against the standards and gates
M-1 produced, and several M-1 gates (`check-layering.sh`, `check-sans-io.sh`,
`check-unsafe.sh`, `check-core-contract.sh`, `check-file-size.sh`) have never
run against Rust code — M0 is their first real exercise, and finding they were
written against an imagined codebase is an expected outcome, not a failure.

## Decisions required first

| Decision | Why now | Background |
|---|---|---|
| Async runtime and its place in the crate graph | Every crate that does async is affected, and doc 10 #32 wants a spike before committing — ⚠️ but doc 10's resolved log says madsim swaps the runtime by `cfg` rather than changing crate structure, so this is smaller than it looks | doc 05 §3, doc 10 #32 |
| Allocator | Doc 18 §3.5 leans mimalloc with jemalloc feature-gated for heap profiling; snmalloc is unbenchmarked and its message-passing free design matches our allocation shape exactly | doc 18 §3.5, doc 10 #30 |
| The five-profile `Cargo.toml` | ⚠️ `lto = false` with `codegen-units = 1` performs **no LTO at all**, and `cargo bench` inherits `release` — both are silent | doc 18 §3.1–3.2 |

⚠️ **Crate boundaries are optimization barriers.** A non-generic `pub fn`
without `#[inline]` is not inlinable across an rlib boundary without LTO, and
doc 18 §0.4 calls this "ruinous" for a byte-level codec split across crates.
The architecture splits `oqueue-buf`, `oqueue-codec`, `oqueue-checksum` and
`oqueue-index` into four crates, so either every hot-path entry point crossing
those boundaries is `#[inline]` **or** the split needs an ADR. Decide it here,
not when M2 is slow.

## Provisional tasks

1. Workspace `Cargo.toml`, resolver 2, shared `[workspace.dependencies]`.
2. The five build profiles, with `lto = "thin"` in release and a bench profile
   that does not silently inherit `release`'s 16 codegen units.
3. `oqueue-core` skeleton: `#![forbid(unsafe_code)]`, no workspace deps.
4. `Clock` seam + fake. ⚠️ Nothing else may read the real time.
5. `ObjectStore` seam + a **trivial** in-memory fake, enough to satisfy the
   fake-per-trait rule the completion condition checks. ⚠️ M1 task 5 replaces it
   with the real one — atomic whole-object PUT, strong single-key
   read-after-write, last-writer-wins on unconditioned races. Two fakes must
   never coexist: M1 rewrites this one, it does not add beside it. Divergent
   conditional-write semantics between two fakes is the highest-risk defect
   class in the project.
6. `KeyProvider` seam + no-op and fake. Present from the start so the encrypted
   and unencrypted paths never diverge (doc 22 §8).
7. Core types and IDs: `TopicId`, `PartitionId`, `Offset`, `ObjectKey`.
8. Error taxonomy in core, with the redaction rules FR-44 will need.
9. The remaining **nine** crate skeletons — `buf`, `codec`, `checksum`, `index`,
   `store`, `coordinator`, `crypto`, `compact`, `broker` — each with `README.md`
   and `AGENTS.md`. ⚠️ `oqueue-crypto` is absent from doc 19's ten-crate layout
   and exists only in `architecture.md`; it is the one most easily dropped.
10. `oqueue-testkit`, dev-only, with the fake-per-trait convention enforced.
11. `#![forbid(unsafe_code)]` everywhere except `buf`, `codec`, `checksum`.
12. `check-layering.sh` run against real crates; fix what it gets wrong.
13. `check-sans-io.sh` likewise — its first encounter with actual `async fn`.
14. Allocator selection wired, with the profiling feature gate.
15. `check-coverage.sh` + **measure and record NFR-55's constant**.
16. `check-budget.sh`'s constant — **measure and record NFR-56** (the script is
    M-1.12; only the number waits for this milestone).
17. Mutation testing wired with diff-narrowing, so cost is O(change).
18. `bin/oqueue` composition root that starts, does nothing, and exits.

## Completion condition

```bash
scripts/gates/m0-complete.sh
```

Asserts: the workspace builds on `x86_64-unknown-linux-gnu` and
`aarch64-unknown-linux-gnu`; every `pub trait` in `oqueue-core` has a fake in
`oqueue-testkit`; `check-layering.sh`, `check-sans-io.sh` and `check-unsafe.sh`
pass; **both** NFR-55's coverage constant and NFR-56's pre-commit budget hold as
numbers in their scripts rather than environment variables; and each was
measured on this workspace rather than carried in.

⚠️ **NFR-56 is named explicitly because it is the one most easily skipped.** M0
is its only possible source — the roadmap lists no other blocker — so a
completion condition that checks coverage and forgets the budget leaves
`check-budget.sh` holding a guessed number permanently.

## Risks and open questions

- ⚠️ **The eleven-crate split is asserted, not measured.** Doc 19 says DAG depth
  sets the build-time floor, and the split is designed for that — but no oqueue
  build has ever been timed. If `oqueue-core` approaches ~40 traits it becomes a
  rebuild bottleneck for the whole workspace; the pre-planned fix is splitting
  `core-types` from `core-traits` (doc 10 #34).
- **`check-*` gates written before any Rust existed will be wrong in places.**
  Expect to fix them here. A gate that passes because it matches nothing is the
  failure mode to watch for — M-1.15's negative tests are what catch it.
- **Neither constant has a defensible starting guess.** Two minutes is a common
  pre-commit figure in general practice; ⚠️ **the corpus states no coverage
  threshold at all** — doc 19 argues only that coverage is weaker than mutation
  testing. Do not go looking for a band it does not contain. Both numbers must
  come from this workspace. ⚠️ Recording a number without measuring it here would make
  every later threshold argument rest on a fiction.

# M1 — Object store seam and conformance suite

**Kind:** crate delivery ·
**Depends on:** M0 ·
**Serves:** FR-30, FR-31, NFR-30

## Goal

`ObjectStore` with three implementations — in-memory, S3, GCS — and one
conformance suite that runs against all of them and records which backends it
has actually been run against.

⚠️ **The fake is the highest-risk component in the project**, and this milestone
is where that risk is either bounded or quietly accepted. Conditional writes
(`If-Match` / `If-None-Match`) are load-bearing for the whole CAS design. If the
fake and MinIO are both *more permissive* than real S3, the result is an
architectural error rather than a test gap — a class of defect that surfaces in
production, under concurrency, months later.

## Depends on

**M0** for the workspace and the `ObjectStore` seam. Nothing else: this crate is
deliberately buildable and testable without a broker.

## Provisional tasks

1. `ObjectStore` trait: `put`, `get(ByteRange)`, `delete(set)`. Listing decided
   per the ADR above and, if kept, on a separate `MaintenanceStore`.
2. Types: `ObjectKey` (never reused), `ByteRange`, `ObjectMeta`, and an
   **opaque** `PreconditionToken`. ⚠️ Not comparable across backends and **not a
   content hash** — multipart and SSE-KMS break that assumption.
3. Error taxonomy and classification: `NotFound`, `PreconditionFailed`,
   `SlowDown`, `Throttled`, `Transient`, `Permanent`. Classification belongs to
   the seam, not to each backend. ⚠️ **Blocked on the error-enum decision
   above** — this task names six variants and no crate, which is how M0 ended
   up with both its seams returning `oqueue-core::Error` without anyone
   choosing that.
4. `Precondition` enum mapping S3's `If-None-Match: *` / `If-Match` to GCS's
   `ifGenerationMatch=0` / `=N`.
5. In-memory fake — **replacing** M0's placeholder rather than sitting beside
   it: whole-object atomic PUT, strong single-key read-after-write,
   last-writer-wins on unconditioned races.
6. Fault injection on the fake: latency distributions, 503 storms, conditional
   -write race interleavings, crash-after-PUT-before-commit.
7. Multipart/resumable abstraction with the limits encoded as types: 5 MiB
   minimum part except the last, 5 GiB maximum, 10,000 parts, 5 TiB object.
8. S3 backend with conditional PUT and conditional `CompleteMultipartUpload`.
9. GCS backend: resumable sessions, 256 KiB chunk multiples, `compose`.
10. `copy_range` server-side (S3 `UploadPartCopy`, GCS `compose`) — M5 needs it
    and it is cheaper to land with the seam.
11. Retry policy driven by error class. ⚠️ **412 is never retried here** —
    retrying a lost CAS silently converts it to last-writer-wins.
12. Per-prefix request-rate governor sized to S3's 3,500 write / 5,500 read per
    second, and GCS's ramp that doubles roughly every 20 minutes.
13. Key layout: computable, offset-aligned keys with hash fan-out. ⚠️ **No
    dependence on lexicographic order** — S3 Express directory buckets do not
    return objects in lexicographical order.
14. Ranged-GET read path with request merging and a sparsity gate.
15. 4 MiB-aligned chunk addressing plus single-flight, so 500 concurrent readers
    do not issue 500 cold GETs.
16. Op-class accounting, so cost is a testable property rather than a review
    convention.
17. The conformance harness: one parameterized body per backend, a recorded
    "which backends has this run against", and a capability matrix so a backend
    declares an operation unsupported rather than silently passing.
18. **The region header's `alg` field**, value `none` on the default path.
    ⚠️ Pulled forward from M8 — a few bytes now against a format migration
    later; doc 10 #40.

Also carried here and **not** a code task: the **madsim / `object_store`
feasibility spike**, deferred out of M-1 because it needs a repo and gates. Its
answer shapes `standards/testing.md`.

## Completion condition

```bash
scripts/gates/m1-complete.sh
```

Asserts the conformance suite passes against the in-memory fake and against
MinIO, and records which backends it has been run against.

⚠️ **Real S3 is deferred and conditional-write behaviour stays marked
unverified until it runs.** The suite is written to doc 04 §6's *documented*
semantics, which narrows the residual risk to "does the implementation match its
own documentation" — it does not eliminate it. Doc 10 #33.

## Risks and open questions

- ⚠️ **An over-permissive fake is worse than no fake**, because it converts a
  visible gap into invisible confidence. This is the milestone's central risk
  and the reason the capability matrix exists.
- **S3 Express is single-AZ** and does not carry Standard's durability. A naive
  Express backend must not be swappable behind the same durability contract.
- **GCS has consistency caveats S3 does not**: IAM/ACL changes and bucket
  recreation are eventually consistent, typically ~1 minute. A fixture that
  creates a bucket and immediately writes passes on S3 and flakes on GCS.
- **GCS sustains roughly 1 CAS/s per object against S3's ~15** — a portability
  hazard for anything built on per-object conditional writes; doc 10 #18.
- **Unverified:** does `object_store`'s dependency tree cross-compile cleanly to
  aarch64-musl (#37)? One CI run settles it, and it should happen before M13
  promises the artifact matrix.

# M-1 — AI development system

**Kind:** AI-native development support ·
**State:** in progress ·
**Serves:** NFR-50, NFR-54

## Goal

Every later milestone is executed by an agent against a set of rules, and **a
rule that arrives after the code it governs has already been violated**. So the
rules, the scripts that enforce them, and the loops that invoke those scripts
come first. Nothing in this milestone is broker code.

After it, an agent can be handed a milestone and drive it to completion
unattended: each task becomes one reviewed commit that leaves the tree green,
each commit is read by an agent that did not write it, and the milestone as a
whole is read once more at its boundary. Nothing in that chain is satisfiable
by claiming it happened.

## Depends on

Nothing. It is the first milestone by construction.

## Completion condition

```bash
scripts/gates/m-1-complete.sh
```

Asserts that every non-negotiable in `AGENTS.md` names a script that exists and
passes, that `tests/gates/negative.sh` proves each gate can fail, and that no
rule remains marked "not yet enforced" except rule 3, which cannot be.

⚠️ **Rule 3 is the permanent exception** — "never claim a test passes without
having run it" is a rule about what an agent says, and nothing checks a claim
against an intention. Every other rule rests on it. The completion condition
asserts it is *marked* unenforceable rather than pretending otherwise.

## Risks and open questions

- ⚠️ **This milestone is well over the 20-task limit `sdd.md` now states** —
  `backlog.md`'s own row count is the only thing that should be asked for the
  live number; a fixed count here would be stale the moment the next task
  lands, the exact defect the boundary review found in this section and in
  `roadmap.md`'s task-count cell (→ **M-1.52**). Several of the excess tasks
  are the commits writing that limit down, and several more are `milestone-review`
  findings the limit did not anticipate. It is the evidence for the rule
  rather than an exception to it. Splitting it now would renumber tasks the
  git history already cites, so the cost is paid once, here, and every
  milestone after it is planned under the cap.
- ⚠️ **A gate nothing invokes is a preference.** `.git/hooks` is not tracked, so
  a fresh clone runs none of these until M-1.14 makes a checkout inherit them.
  Until then the enforcement is real only on machines where it was installed by
  hand.
- ⚠️ **Two constants cannot be chosen here, and one task is blocked on that.**
  `check-budget.sh` is **M-1.12**, but its acceptance criterion ("suite over
  budget fails") needs NFR-56's number, and the number needs a workspace to
  measure — so the backlog records it as *blocked rather than guessed*, and the
  roadmap assigns NFR-56 to M0. ⚠️ **`m-1-complete.sh` must not require it.**
  That gate asserts every *non-negotiable* names a passing script, and
  `check-budget.sh` is named by no non-negotiable in `AGENTS.md`; wiring it in
  anyway would deadlock M-1 behind a milestone that comes after it. NFR-55's
  coverage gate has no M-1 task at all and is straightforwardly M0's.
- **The reviewer's independence is bought by the harness, not by the artifact.**
  The diff hash binds a verdict to bytes; it does not prove the reviewer was not
  the author. Doc 21 §4–5, and stated in `AGENTS.md` rather than implied away.

# M2 — Kafka wire protocol: produce and fetch

**Kind:** functional ·
**Depends on:** M0 ·
**Serves:** FR-1, FR-2, FR-3

## Goal

An unmodified Kafka client connects, negotiates versions, produces, and fetches.
The data goes nowhere durable yet — M3 supplies offsets and the index — but the
wire is real, and "real" is decided by librdkafka rather than by our tests.

## Depends on

**M0** for the workspace and `oqueue-codec`/`oqueue-checksum`. Deliberately not
M1: the protocol layer can be built against an in-memory partition stub, and
keeping it independent is what lets both proceed without blocking.

⚠️ **That independence is why FR-32 is not served here.** Batching records from
many topics into one object is verified by "a flush with N topics issues one
PUT", and this milestone has no object storage to PUT to. It belongs to M3,
which is the first milestone composing the store and the wire.

## Decisions required first

| Decision | Open question | Background |
|---|---|---|
| Hand-roll `oqueue-codec` vs wrap or vendor `kafka-protocol` | **#4** | doc 02 §6.4, doc 05 §2 |

⚠️ **This decision is larger than it looks.** Kafka's own broker and clients are
generated from `clients/src/main/resources/common/message/*.json`, which declare
per-field `versions`, `nullableVersions` and `flexibleVersions`. Doc 02 §6.4
calls that JSON "more authoritative and certainly more precise than the prose
protocol guide", and says codegen against it avoids the two biggest sources of
compatibility bugs: manually tracking version-gated field presence, and manually
implementing the flexible-versions rules per message. `kafka-protocol` v0.17
tracks Kafka 4.1.0 but has a small maintainer base — so the real choice is
*hand-roll, depend, or generate*, and it decides most of this milestone's shape.

## Provisional tasks

1. `oqueue-checksum`: CRC-32C over `crc-fast`, plus `crc32c_combine`.
   ⚠️ **`crc32fast` is the wrong polynomial** — it implements CRC-32/IEEE, Kafka
   mandates Castagnoli, and using it produces batches every client rejects **with
   no compile error**. Doc 18 §4.3.
2. SIMD dispatch struct cached in a `OnceLock`, with an env override.
   ⚠️ Dispatch per RecordBatch, never per field.
3. Primitive codec: big-endian ints, strings, bytes, classic arrays.
4. Varint/zigzag with a SWAR decoder. ⚠️ Reject `varint-simd` — it reads up to
   16 bytes past the varint, which is a buffer overrun on untrusted input.
5. Flexible-version primitives: compact strings/arrays and tagged fields.
6. **Per-(API, version) flexibility table.** ⚠️ Not a global cutover: Produce is
   flexible from v9, Fetch from v12, ApiVersions from v3, SaslHandshake never.
7. Length-delimited frame codec with correlation-ID extraction.
8. Request/response headers v0–v2, **including the `ApiVersions` special case**:
   its body may be flexible while its response header is always v0. Emit a v1
   header and every client fails at the first byte after connect.
9. Connection task: read/write split, pipelining, out-of-order responses,
   bounded channels for backpressure.
10. RecordBatch v2 header: the 61-byte fixed layout, `magic != 2` rejected.
11. Attributes bitfield: compression, timestamp type, transactional, control,
    delete-horizon.
12. CRC verify on ingest, and the **header-only offset rewrite path**.
    ⚠️ Because `offsetDelta` is relative and `partitionLeaderEpoch` sits outside
    the CRC, assigning offsets decodes **zero varints**. Doc 18 §4.4 calls this
    structural decision worth more than any SIMD work.
13. Record-level iterator, **opt-in per code path** and not on produce/fetch.
14. Compression seam: none, lz4, zstd wired; gzip and snappy behind features.
15. `ApiVersions` v0–v3 with the `UNSUPPORTED_VERSION` v0-bodied fallback.
    ⚠️ Answered **before** authentication.
16. `Metadata`, honouring `AllowAutoTopicCreation` from v4.
17. `Produce` v3–13 (v0–2 removed by KIP-896) and `Fetch` v4–17, echoing session
    fields and parsing `IsolationLevel` even if only one level is honoured.
18. Golden-byte corpus from real clients, plus a librdkafka conformance harness
    and the first version of a public protocol-support matrix.

Also carried here and deferred into M2 by M0's checkpoint review:
**`scripts/fuzz.sh`**, which `security.md` rule 5 names and nobody has written.
⚠️ It belongs with a decoder rather than with the workspace milestone —
`testing.md` rule 24 puts a fuzz target on every decoder, and M2 builds the
first one. Until it exists, rule 5 reads as enforced and is not.

Also deferred into M2, by M0's **boundary** review: **how a `minor` review
finding gets scheduled** — a decision, not a task. `review.md` rule 15 sends a
minor to the commit body; rule 16 four lines below calls a finding living where
nothing reads it one nobody will act on. M0's second half recorded roughly
thirty that way and none became a backlog row. ⚠️ **The fix is a procedure** —
some step that harvests commit bodies at a milestone boundary — and choosing one
is for whoever owns the loop, which is why M0's review recorded it as
`bcf5d6f697f2` and argued it rather than re-specifying `review.md` on its own
authority. ⚠️ **M2 because this is the first milestone whose minors are about
protocol code rather than prose**, and because the interim rule 15 now states —
write the row in the *next* commit — is a workaround that removes the pressure
to decide, so it needs a date. `roadmap.md`'s deferral table carries the row.

## Completion condition

```bash
scripts/gates/m2-complete.sh
```

Asserts: librdkafka and the Java client complete produce and fetch round trips
against a stub partition; every advertised API returns something other than
`UNSUPPORTED_VERSION` (FR-2); the golden-byte corpus re-encodes byte-exactly;
and the CRC differential test against a scalar reference passes.

## Risks and open questions

- ⚠️ **librdkafka enables the idempotent path by default**, forcing an
  `InitProducerId` call even when the application never asked for transactions.
  Key 22 is M11's, so M2 must either stub it or document that test clients set
  `enable.idempotence=false`. **Decide explicitly** — discovering it during the
  first real client test is the common way this milestone slips.
- ⚠️ **Broker identity is stateful in a way a stateless fleet is not.** Clients
  inspect both node ID and hostname to decide whether a topology change
  occurred. The reference system's fix exploits Kafka clients treating hostnames
  case-sensitively while DNS is case-insensitive. `Metadata` responses need a
  deliberate strategy here, not whatever is convenient.
- **Downconversion to message format v0/v1 is refused, not implemented** —
  following KIP-110's own precedent of declining a costly conversion. ⚠️ The
  corpus supports `UNSUPPORTED_COMPRESSION_TYPE` **only for the zstd-to-old-
  client case**; refusing an unsupported *message format* needs an error that
  names the format, or the client is steered toward reconfiguring a compression
  setting that was never involved.
- **Do not gate the codec on instruction counts.** Valgrind emulates CPUID, so
  feature detection returns false and a benchmark silently measures a fallback
  path production never runs. Doc 18 §2.2.
- **Compatibility is a permanent cost, not a milestone.** Fluvio started
  Kafka-wire-compatible and consciously abandoned it once tracking the
  protocol's evolution outweighed the features they wanted. Doc 02 §7.5.

# M3 — Coordinator: offset sequencing and the index

**Kind:** functional ·
**Depends on:** M1, M2 ·
**Serves:** FR-10, FR-11, FR-12, FR-13, FR-32, NFR-2, NFR-3, NFR-21

## Goal

Produce becomes durable and ordered: a record is acknowledged only after it is
in object storage **and** its position is committed, offsets are monotonic and
gap-free per partition under concurrent producers, and a reader resolves
offset→object through an index rather than by listing anything.

⚠️ **"Its position is committed" is committed to an *in-memory* log in M3**,
and the sentence above overclaimed until M3's checkpoint review said so
(`M3.19`). `FakeMetadataLog` is the only `MetadataLog` this milestone builds;
the durable engine is doc 10 #12, which `ADR-0020` point 5 defers and
`roadmap.md` assigns to **M6**. So M3's ack means *the object is durable and
the position is committed to a log that does not survive the process* — a
restart re-bases at `Offset::ZERO` over objects that already hold those
offsets. ⚠️ **FR-10 is met regardless**: it says "durable in object storage",
and says nothing about the metadata log. What is deferred is recorded in
`roadmap.md`'s deferral table and received by `M6.md`, rather than left to be
discovered by whoever first restarts a broker.

This is where the architecture stops being a diagram. Everything object storage
cannot do — atomic append, cheap CAS at offset-assignment rate — is worked
around here or not at all.

## Depends on

**M1** for the store, **M2** for the wire. It is the first milestone that
composes rather than builds a layer.

## Provisional tasks

1. `CommitVersion(u64)` and the single monotonic allocator stamping every
   committed record. ⚠️ One scalar — staleness must be a `u64` compare, never a
   timestamp or hash comparison.
2. Metadata log record enum, **event/delta shaped rather than key-value**. That
   shape is what makes snapshotting right and compaction wrong later (M6).
3. `CoordinatorEpoch` in every response, so readers can revalidate after a
   failover rewinds the log.
4. **Offset assignment at commit time, not flush time.** The serialization point
   is the log append, which is what lets many writers PUT concurrently without
   coordinating.
5. Assign → journal → ack ordering. No offset is externally visible before its
   log record commits.
6. ⚠️ **Error paths return `-1`, never `0`.** A plausible-looking offset on an
   error path turns an availability bug into a safety bug; it happened in a peer
   system and is documented in doc 13 §8.
7. `ObjectRef` layout targeting ~40 bytes per entry. Size is a design constraint
   here, not an afterthought — see the growth arithmetic below.
8. Two-tier index: inline byte ranges for the tail window, object-refs resolved
   through the in-object footer for history.
9. `MaterializedIndex` behind a trait, documented as a **cache, not the source
   of truth** — droppable and refillable.
10. Batched apply, committing every N ≥ 1,000 entries. ⚠️ Individual commits do
    not meet the required rate on any candidate engine; batching is mandatory,
    not an optimization.
11. `applied_upto` persisted **in the same transaction** as the entries it
    covers — what makes warm restart replay a delta rather than everything.
12. `find_batches(topic, partition, start, max_bytes) → ordered [ObjectRef]`.
13. High watermark **derived** from the index, never independently set. There
    should be no setter.
14. Deltas applied strictly in `CommitVersion` order; out-of-order rejected.
15. Push subscription for tail deltas, bounded-page pull for history.
16. Three read modes: `Stale` for Fetch, `AtLeast(v)` for read-your-writes,
    `Linearizable` for `ListOffsets`.
17. Wire the delta wakeup into the existing `fetch.max.wait.ms` park, so
    freshness costs about a millisecond and introduces no new semantics.
18. Index growth as an **enforced, alarmed quota with an explicit degraded
    mode** — not a dashboard. Cleanup defaults on.
19. Multi-topic flush batching (FR-32): one flush covering N topics issues
    **one PUT**. ⚠️ Inherited from M2, which cannot serve it — it has no object
    storage. This is what the whole cost model rests on. ⚠️ **Also where the
    region header's `alg` field lands**, deferred here from an original "M1"
    reading of doc 10 #40 (`M1.7`; `roadmap.md`'s deferred-into-a-later-milestone
    table): this is the first commit that defines a bundled object's internal
    structure, so it is the first commit with a region header to carry the
    field. Default path writes `none`; `M8` is where a decoder acts on
    anything else. ⚠️ **And where a streaming multipart writer, sealed with a
    `Precondition`, needs designing** — deferred here from `M1.16` (ADR-0013;
    `roadmap.md`'s deferred-into-a-later-milestone table): `object_store`
    exposes no public way to condition a `CompleteMultipartUpload`, and
    `ObjectStore::put`'s complete-in-memory-`Vec<u8>` shape cannot express a
    streaming writer of unknown final size regardless of that gap. This task's
    flush batching is the first thing that actually accumulates a growing
    object across more than one write, so it is the first real caller —
    designing the seam capability against whatever `object_store`'s public API
    looks like by then (ADR-0013's three alternatives — hand-rolled signing, an
    `HttpConnector` interception hack, or an upstream fix — are still live, not
    settled) is this task's to do, not `M1`'s to have assumed away.
    ⚠️ **And where `ADR-0008`'s `RetryConfig` wiring lands** (`M2.10`'s status
    note; `roadmap.md`'s deferral table): the first real attempt-loop caller
    configures the vendor retry from `RetryPolicy`'s constants, or supersedes
    the premise with its own ADR.
20. ⚠️ **The durability conformance case, and the `Capabilities` flag to carry
    it** — deferred here from M1 (`roadmap.md`'s deferred-into-a-later-milestone
    table, via `M1.58`). `ADR-0005` guarantee 1 promised the fake's crash
    clause is skipped "explicitly rather than by omission"; `M1.37` measured it
    skipped by omission — two flags, neither about durability, and the fake's
    `crash_after_put_before_ack` exercised by no case. The FR-10
    fault-injection test this milestone's completion condition already demands
    is the same scenario: write it as a conformance case gated by a durability
    capability flag, so a backend that cannot run it skips *explicitly* and the
    suite's "never silently passing a case the backend never ran" claim becomes
    true of durability too.

Asserts: a property test over concurrent producers yields exactly `0..k` per
partition with no gaps (FR-11); a fault-injection test killing between PUT and

**zero GETs** (FR-12); and a cold fetch issues a bounded number of GETs and

exactly one PUT (FR-32).

## Risks and open questions

- ⚠️ **The staleness hazards are the substance of this milestone**, and each
  needs a loud failure mode rather than silent degradation. Two of five bugs
  found in a peer system by an independent audit were stale-cache problems
  producing *silent wrongness* — successful polls returning no records.
  - `ListOffsets` from a stale cache reports a log-end-offset below truth,
    producing **negative consumer lag**. Route it to the authoritative
    coordinator; never derive it from cache.
  - Produce-then-immediately-consume must work: carry the produce response's
    commit version as a session watermark and fetch at `AtLeast(v)`.
  - A 404 is **never** "end of log" — refresh the index, retry, and only then
    return `OFFSET_OUT_OF_RANGE`. Instrument it; a nonzero rate means M5's
    deletion delay is too short.
- **Index growth is the constraint people underestimate.** At ~40 bytes and the
  modelled rate this is roughly 14 GB/day and ~97 GB over a 7-day retention —
  which does not fit in an agent's memory. It is what forces M5's compaction to
  be a metadata mechanism as much as an I/O one.
- ⚠️ **NFR-13 is UNDERIVED and gates this milestone's arithmetic.** The tail/
  history split in task 8 is sized against an assumed workload. Doc 10 #25.
- **Do not put CAS-on-object-storage on the offset stream.** It belongs in the
  low-frequency control plane — compaction claims, leader epochs, checkpoint
  pointers. The published ceiling for the CAS-only approach is about one entry
  per second per namespace.

# M11 — Idempotent producers

**Kind:** functional ·
**Depends on:** M3 ·
**Serves:** FR-14

## Goal

`enable.idempotence=true` works: a producer gets an ID, sequences its batches,
and a retried batch is deduplicated rather than written twice.

⚠️ **This is less optional than its `provisional` status suggests.** librdkafka
enables the idempotent path **by default**, which forces an `InitProducerId`
call even when the application never asked for transactions. Until this lands,
M2's plan requires either a stub or a documented instruction that test clients
set `enable.idempotence=false` — and shipping v1 with that instruction intact
would mean the default configuration of the most widely used Kafka client does
not work.

## Depends on

**M3**, for offsets and a durable write path to deduplicate against. It could be
pulled ahead of M4 — nothing in it needs consumer groups — and sits after only
because consumer groups are worth more.

## Decisions required first

| Decision | Open question | Background |
|---|---|---|
| Idempotency strategy | **#5** | doc 06 §6. The reference system uses retroactive tombstones and has documented librdkafka compatibility gaps; the local-consensus alternative is not available to us. ⚠️ This decision also sets how much of FR-15 (transactions, post-v1) stays reachable later — choosing a mechanism that forecloses transactions is a decision about v2, made here |

## Provisional tasks

1. `ProducerId` and `ProducerEpoch` types, and their place in the coordinator's
   state.
2. `InitProducerId` (22): allocate, fence an old epoch, and return.
3. Producer-ID allocation that survives coordinator failover — a reused ID with
   a stale epoch is a correctness problem, not an inconvenience.
4. Sequence-number tracking per (producer, topic, partition).
5. Duplicate detection on the produce path, against the recorded sequence.
6. `OUT_OF_ORDER_SEQUENCE_NUMBER` and `DUPLICATE_SEQUENCE_NUMBER` returned where
   Kafka returns them, so client retry logic behaves.
7. Expiry of idle producer state, bounded rather than unbounded.
8. The `RecordBatch` producer fields (`producerId`, `producerEpoch`,
   `baseSequence`) honoured on ingest — M2 decoded them and ignored them.
9. Interaction with the flush batcher, **shaped by the #5 ADR and not before
   it**. ⚠️ The two mechanisms differ here and the difference is not cosmetic:
   dropping a duplicate before the PUT keeps the bytes out of storage, while the
   retroactive-tombstone approach writes the batch and then stops the metadata
   store returning it — the bytes physically remain until compaction. Do not
   write a task, a test, or a gate that assumes either until #5 is recorded.
10. Fencing on epoch bump, with a test that a zombie producer is refused.
11. Conformance: librdkafka with `enable.idempotence=true` (its default) end to
    end, and a duplicate-sequence test that observes deduplication.
12. Remove M2's workaround — whichever of the stub or the documented
    `enable.idempotence=false` instruction was chosen — and assert it is gone.

## Completion condition

```bash
scripts/gates/m11-complete.sh
```

Asserts: a client conformance test with `enable.idempotence=true` produces
successfully; **a duplicate sequence number is never observable to a consumer**
(FR-14); a fenced producer epoch is refused; and M2's workaround no longer
exists in the tree.

⚠️ **"Never observable to a consumer", not "never written."** Whether the
duplicate's bytes reach object storage at all is decided by the #5 ADR, and a
completion condition written the other way would be unsatisfiable under the
retroactive-tombstone mechanism — leaving the choice between reopening the
decision and weakening a gate, which non-negotiable 2 forbids.

## Risks and open questions

- ⚠️ **Idempotence without transactions is a partial guarantee, and the
  difference matters to users.** FR-15 is deferred with nothing scheduled, so
  v1 offers per-partition deduplication and not exactly-once across partitions.
  Say so publicly rather than letting `enable.idempotence=true` working imply
  more than it does.
- **The reference implementation of this approach has documented client
  compatibility gaps** — doc 06 §6. Expect the conformance run, not the unit
  tests, to be where those surface.
- **Producer-state expiry is a memory bound nobody has sized.** At the tenancy
  shape M7 targets, per-producer state is another per-principal cost, and the
  interaction is unmodelled.

# M13 — Release engineering and the artifact matrix

**Kind:** build ·
**Depends on:** M12 ·
**Serves:** NFR-40, NFR-41, NFR-42, NFR-43

## Goal

A release is one binary per `(os, arch)`, buildable with only cargo and a C
compiler except the FIPS artifact, running on the oldest glibc this project
commits to, on both Linux architectures, first-class.

## Depends on

**M12**, because a release artifact is only worth cutting once the product
surface — admin included — is complete. Nothing about this milestone is
gated on encryption or scale; it could in principle move earlier, but a
release process exercised before the product exists tests nothing real.

## Decisions required first

| Decision | Open question | Background |
|---|---|---|

## Provisional tasks

1. `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` as the two
   first-class release targets, both native-built rather than cross-compiled
   — free arm64 runners make native builds beat cross-compilation.
2. `cargo-zigbuild` wired to the chosen glibc floor.
3. Runtime CPU-feature dispatch verified in the release build: `x86-64-v2` /
   aarch64 `+lse,+crc` baseline, everything above it behind dispatch — this is
   M2's CRC-32C dispatch exercised in the actual release artifact, not just in
   tests.
4. A clean-container build test: the whole workspace builds with only cargo
   and a C compiler present, except the FIPS artifact (NFR-42).
5. The FIPS artifact as a **separate build job**, with its cmake and Go
   dependencies isolated to that job so the default build's dependency
   footprint is unaffected.
6. musl target evaluated and either adopted or explicitly rejected — doc 20
   flags the default musl allocator as 10-40× worse under concurrency, which
   promotes the allocator choice from M0 to a release-blocking constraint if
   musl is chosen.
7. Smoke test on the oldest supported distribution for the chosen glibc floor
   (NFR-41).
8. CI matrix building and testing on both architectures (NFR-40).
9. macOS in the CI matrix for the fast test tiers only — explicitly not a
   release target (NFR-43).
10. Release artifact naming and versioning, including how the FIPS build is
    distinguished from the default one in a filename a downloader can trust.
11. A reproducibility check: two builds from the same commit produce
    byte-identical (or at least behaviourally identical, if full byte
    reproducibility is not pursued) artifacts.
12. Signing and checksums for release artifacts.
13. The aarch64-musl cross-compilation question resolved (open question #37)
    before the matrix is documented as supporting it.
14. Container images built from the release binaries, for the deployment
    shapes this project actually expects to be run in.
15. A documented, tested upgrade path: an old binary's on-disk-format
    expectations (there are none, by NFR-44) versus its object-format
    expectations (there are several, by M1/M8) — what a rolling upgrade
    requires.

Also carried here by ADR-0007 (`M0.13`): ⚠️ **the jemalloc page-size trap.**
`tikv-jemallocator` bakes in the *build host's* page size, so an aarch64
artifact built on a 4 KB-page runner aborts at startup on a 64 KB-page kernel —
`portability.md` rule 9 makes this project's builds native, which does not avoid
it. Any release artifact carrying the `heap-profiling` feature needs
`JEMALLOC_SYS_WITH_LG_PAGE=16`, or the feature must be excluded from release
builds deliberately.

## Completion condition

⚠️ **Includes the jemalloc page-size trap ADR-0007 carries here**: any release
artifact built with `heap-profiling` needs `JEMALLOC_SYS_WITH_LG_PAGE=16`, or
the feature is excluded from release builds deliberately. A gate written from
the assertions below without this passes while shipping a binary that aborts
on every 64 KB-page kernel.

```bash
scripts/gates/m13-complete.sh
```

Asserts: a clean-container build succeeds with only cargo and a C compiler,
except the FIPS job (NFR-42); the CI matrix builds and tests both Linux
architectures plus macOS for fast tiers (NFR-40, NFR-43); a smoke test passes
on the oldest supported distribution at the chosen glibc floor (NFR-41); and
the FIPS and default artifacts are both produced from one release run with
distinguishable names.

## Risks and open questions

- **The glibc floor is unresolved and this milestone cannot proceed past task
  2 without it.** It is stated here as a product decision because doc 20 is
  explicit that the corpus does not make it — someone has to.
- ⚠️ **musl's allocator cost is not a micro-optimization at this milestone's
  scale of consequence.** If musl is chosen for portability reasons without
  addressing the allocator, the release artifact silently regresses NFR-1's
  latency claim under concurrency — a build decision quietly breaking a
  performance requirement three milestones removed from where it was set.
- **Reproducibility is listed as a task but not gated.** If it turns out to
  be expensive to achieve, that is a finding for this milestone's boundary
  review, not a reason to weaken the completion condition.
- **This milestone has no dependency on M14.** A release built here has not
  yet had its performance claims validated — that is deliberate ordering
  worth restating: M13 proves the artifact runs where it should; M14 proves
  it runs at the speed claimed. Shipping M13's artifact before M14 completes
  would be premature.

# Argued review findings.
#
# A blocking review finding is resolved in exactly one of two ways (doc 21 §6):
#
#   1. Fixed   — the diff changes, the hash changes, the review re-runs
#   2. Argued  — an entry here naming the finding and why it is not a defect
#
# ⚠️ When the verdict is `changes-requested`, every **major** finding needs the
# same treatment. Otherwise a reviewer asks for changes, the commit lands, and
# the findings survive only in a gitignored directory.
#
# ⚠️ The entry must be **staged**. An unstaged line is ignored: it would suppress
# a finding while leaving nothing in the commit to show for it.
#
# Format: <id>  <reason>
#
# ⚠️ The reason is required. An id on its own is refused, because it suppresses
# a blocking finding while recording nothing about why — which is exactly the
# quiet growth this file exists to prevent.
#
# ⚠️ **This file serves two reviews, and their ids are derived differently.**
# Nothing in a line says which, so a reader re-deriving an id needs to know:
#
#   per-commit    `scripts/review.sh record` prints it; `check-reviewed.sh`
#                 prints it again when one is unresolved.
#                 id = sha256(file + "\0" + summary), truncated to 12 hex.
#   milestone     `scripts/milestone-review.sh record` prints it;
#                 `check-milestone-review.sh` prints it again when unresolved.
#                 id = sha256(kind + "\0" + summary), truncated to 12 hex.
#                 ⚠️ A cross-cutting finding has no single file, which is why
#                 its id cannot use one — that is the whole point of the outer
#                 loop. Both gates match this file's lines undifferentiated.
#
# Either way the id is stable across unrelated edits, so arguing a finding does
# not have to be repeated every time the diff moves for some other reason. ⚠️ A
# milestone finding is argued when its right outcome is **not** a backlog row —
# typically `kind: spec-wrong`, where the outcome is a decision. Say which
# review a line came from in its reason; nothing enforces that.
#
# ⚠️ This is a file nobody may grow quietly. A growing argued-list is itself a
# finding: it means a reviewer is being systematically overruled, and one of the
# two sides is systematically wrong. Read it at every milestone boundary.
#
# Empty is the correct state.

# Which backends the conformance suite has been run against, and which it
# has not. `M1.21`, `FR-31`'s own verification method.
#
#   <backend>  <status>  <why>
#
# Two columns of fact and one of reason, in the same shape and for the same
# purpose as `baselines/review.txt`, `mutants.txt` and `unsafe.txt`:
# ⚠️ **a list nobody grows quietly.** A `not-yet-run` row is a claim a
# reviewer can check, not a gap nobody wrote down.
#
# ## What the two statuses mean
#
# `verified`   -- the suite has actually been executed against this backend,
#                 and `scripts/gates/m1-complete.sh` re-runs it and refuses to
#                 pass if it does not. ⚠️ **Re-established on every *completed*
#                 run of that gate** -- a run on a machine with no Docker skips
#                 the container half and still exits 0, saying so on stdout but
#                 not in its exit code. So this row is a fact about the last
#                 run that actually reached MinIO, which is not necessarily the
#                 last run. `M1.34` is the CI job that would make it a
#                 schedule; until then, read the gate's output, not just its
#                 status.
# `not-yet-run` -- nothing has executed the suite against this backend. ⚠️ Not
#                 "expected to work": the whole point of naming it here is that
#                 nobody may quietly read an absent row as a passing one.
#
# ⚠️ **`m1-complete.sh` checks this file in both directions.** Every
# `verified` row must appear in the roster the test run records, and every
# roster entry must appear here — the second half is not symmetry for its own
# sake. `M1.21` found sixteen invented backend names (`concurrent-0` ..
# `concurrent-15`) sitting in that roster, written by the recording
# mechanism's own unit test, so the artifact claimed eighteen conformance-
# tested backends of which sixteen did not exist. Nothing noticed, because
# nothing read the file back.

fake  verified  In-memory FakeObjectStore, oqueue-core. Declares FULL capabilities and runs every case at T1 -- no container, no network, so this row is re-established by `cargo test` alone. ⚠️ **Including `injectable_ack_loss` since `M3.15`** -- a harness capability, not a durability property: nothing can *tell* S3 to drop an acknowledgement after a durable write, so only a backend that can be *told* to misbehave exercises `ADR-0005` **guarantee 2** (a failed put is not proof of absence) — ⚠️ **the fake and, since `M10.3`, `sim` below**, which was written when the fake was the only one and said so. ⚠️ **Guarantee 1's crash clause is still covered by nothing here**, and cannot be: no single-process fake can show that `Ok` survives a process death. `ADR-0005`'s Consequences say so and `M1.44` deferred it to `M15`'s real-backend verification -- do not read this row as retiring that.
s3  verified  S3Store against a MinIO container at T2 (`tests/it/s3_minio.rs`), plus the real multipart path from `M1.16`. ⚠️ **Not at FULL since `M3.15`, and that is the point**: `injectable_ack_loss` is declared off and `a_failed_put_is_not_proof_of_absence` is skipped and *named in the report* rather than quietly not asked about -- the explicit skip `M1.37` found was happening by omission. ⚠️ **This is not a durability gap in S3.** S3 is the backend that actually provides `ADR-0005` guarantee 1; what it lacks is a way to be *told* to lose an acknowledgement. Credentials and endpoint come from `AWS_*` set before the process starts, never from a literal (`security.md`).
sim  verified  `S3Store` over a deterministic in-process S3 that answers `object_store`'s `HttpService` (`tests/it/sim/`, `M10.2`/`M10.3`, `ADR-0027`). ⚠️ **`s3`'s code path, not a second implementation of it**: the same `S3Store`, the same `object_store` request construction and response handling, with the socket replaced above HTTP — so a status code becomes one of our errors here exactly as it does against MinIO. ⚠️ **At FULL, which `s3` cannot be**: a model *can* be told to store bytes and then fail, so this is the only backend besides the in-memory fake that runs `a_failed_put_is_not_proof_of_absence` (`ADR-0005` guarantee 2), and it runs it against the real S3 client rather than against a fake of the trait. ⚠️ **It proves nothing below HTTP** — not the socket, TLS, connection pooling, or `object_store`'s own retry *timing* (`testing.md`) — which is why `s3` keeps every case it has and this row does not retire it. ⚠️ **The retry *budget* is the production one**, because review found the sim inheriting `RetryConfig::default()`'s `max_retries: 10` where `from_env` installs `max_retries: 2` — eleven attempts against three: a model eight attempts more patient than the shipped client would let a fault run "prove" survival of a storm no deployment survives. ⚠️ **And the injected ack loss answers a single unretried 400**, chosen so it classifies as the fake does — not because S3 answers one: a real lost ack is a dropped connection or a 5xx that spends the retry budget first, so this arm is one attempt with no retry where a real lost ack spends the whole budget — three attempts, two retries. `M10.7` is where a sticky 5xx would make it faithful. T1: no container, no network, so `cargo test` alone re-establishes it.
gcs  not-yet-run  GcsStore is fully built and covered at T0, but no GCS emulator round-trips `object_store`'s actual request shape: `fake-gcs-server` routes the XML PUT to a JSON handler that demands an `uploadType`, and Google's own `storage-testbench` stores the object but returns no ETag or generation header, so the client fails before this crate is reached. Both confirmed against live containers, not inferred. ADR-0014.
s3-real  not-yet-run  Real AWS S3, deliberately deferred -- doc 10 #33. The suite is written to doc 04 section 6's *documented* conditional-write semantics, which narrows the residual risk to "does the implementation match its own documentation" rather than eliminating it.
gcs-real  not-yet-run  Real Google Cloud Storage, deferred for the same reason as `s3-real` and additionally blocked by `gcs` above having no emulator to fail fast against first. doc 10 #33.
